# Handoff WI-06 – GitHub: App-Identitäten, Source-Adapter, Dependencies

Branch `wi-06-github`. Gate: `npm install && npm run check` grün. **Keine Änderungen an `src/core`**, keine
neuen Dependencies, `package.json` unverändert.

## Umgesetzt

### `src/identities/` (Public API über `index.ts`)
- `GitHubAppCredentialProvider(identities, deps)` implementiert `CredentialProvider`.
  - `identities: Record<id, { appId, installationId, privateKeyEnv }>` (camelCase; WI-02/WI-10 mappt die
    YAML-Felder `app_id`, `installation_id`, `private_key_env`).
  - `deps: { clock, fetch?, timers?, logger?, env? (default process.env), redactor?: SecretRedactor, apiBaseUrl?, http?, refreshMarginMs? (5 min) }`.
  - JWT RS256 via `node:crypto` (`iat = now-60 s`, `exp = now+9 min`, `iss = App-ID`), Token über
    `POST /app/installations/{id}/access_tokens`, Cache bis `expiresAt - 5 min`, parallele Anfragen je Identität
    dedupliziert, `invalidate(id)` verwirft Cache (und verhindert, dass ein älterer In-flight-Austausch ihn wieder befüllt).
  - Fehler: 4xx/ungültige Antwort/fehlende Env/ungültiger Key/unbekannte Identity → `SourceError('auth', retryable:false)`;
    5xx/Netz/Rate-Limit behalten ihre Art (`transient`/`rate_limited`, retryable).
  - Redaction: Key (roh, `\n`-escaped **und** normalisiert), JWT (während des Austauschs) und Tokens werden beim
    `SecretRedactor` registriert; abgelaufene Tokens werden beim nächsten Austausch wieder entfernt (begrenzte Registry).
- `createAppJwt`, `parsePrivateKey`, `normalizePrivateKeyPem` (PEM mit echten Zeilenumbrüchen, `\n`-Escapes, CRLF, Quotes).

### `src/sources/` (Public API über `index.ts` → `src/sources/github/index.ts`)
- **HTTP-Client** `GitHubHttpClient` (`http.ts`): injizierbares `fetch`, `X-GitHub-Api-Version` gepinnt
  (`GITHUB_API_VERSION = '2026-03-10'`), `Accept: application/vnd.github+json`, `User-Agent`, Request-Timeout (30 s).
  - Fehlerklassen über `SourceError`: 401 `auth`, 403 `forbidden`, 404/410 `not_found`, 429 bzw. 403 mit
    `x-ratelimit-remaining: 0`/`retry-after`/„rate limit“ → `rate_limited` (`retryAfterMs` aus `Retry-After` oder
    `X-RateLimit-Reset`), 5xx/Netz/Timeout `transient`, sonst `invalid`.
  - Retries (Default 2) mit `Timers` (FakeClock-testbar): `transient` nur bei idempotenten Requests (GET bzw.
    `idempotent: true`), `rate_limited` immer (Request wurde nicht ausgeführt); Wartezeit > `maxRetryWaitMs` (60 s)
    → sofort `rate_limited` werfen. Nicht-idempotente Requests bei Netzfehler/Timeout/5xx → `outcomeUnknown: true`.
  - `paginate()` folgt `Link: rel="next"` (nur gleiche Origin – Token geht nie an fremde Hosts), max. 50 Seiten.
  - Fehlermeldungen enthalten Methode, Pfad, Status und GitHubs `message` (gekürzt), nie Header/Token/Request-Body;
    die rohe `fetch`-Exception wird nicht als `cause` angehängt.
- **Adapter** `GitHubSourceAdapter` / `githubSourceFactory` / `createGitHubSourceFactory({ timers?, http?, httpOptions? })`,
  Typ `github`, Config `GitHubSourceConfig { owner, repository, identity, apiBaseUrl?, webBaseUrl? }`.
  - `fieldDefinitions()` = `GITHUB_FIELD_DEFINITIONS` (Felder lt. WI; `labels` pushdown `contains`, `state` pushdown
    `equals|in`; `dependencies.*` `expensive: true`).
  - `listCandidates({filter})`: `GET /repos/{o}/{r}/issues` (Issues+PRs, `sort=created&direction=asc`), Pushdown nur
    aus Top-Level-Prädikat bzw. `all`-Konjunktion (`labels contains` → `labels=a,b`, `state equals/in` → `state`),
    Default `state=open`. Rest wertet der Aufrufer lokal aus.
  - `itemId` = Nummer als String, `key = sourceItemKey(sourceId, itemId)`, `type` `issue|pull_request`, `url` = `html_url`.
  - `getItem`: 404/410 und ungültige IDs → `null`; transferierte Issues (anderes `repository_url`) → `null`.
  - `parseItemRef`: `123`, `#123`, `owner/repo#123`, `https://github.com/o/r/issues/123`, `/pull/123[/files][#…]`;
    Owner/Repo case-insensitive, fremde Repos/Hosts → `null`.
  - `resolveFields` (Batch-Vertrag aus WI-01): alle `dependencies.*` aus **einem** paginierten Aufruf
    `GET …/issues/{n}/dependencies/blocked_by` (Cross-Repo-Einträge inkl. Zustand); kein Cache über Aufrufe.
    Jeder Fehler (403/404/5xx/Rate-Limit/Auth, unerwarteter Zustand) → `blocked_by_*`/`blocked` = `known:false`,
    `dependencies.status = {known:true, value:'unknown'}`. Nur ein abgebrochenes Signal wirft.
    **Fail-closed-Zusatz:** Ist `issue_dependencies_summary.total_blocked_by` des Item-Snapshots größer als die
    sichtbare Liste (Blocker in Repo ohne Zugriff), ebenfalls `unknown`. Der Summary-Wert hängt per `WeakMap` am
    Item-Objekt (Metadatum des Snapshots, kein Feldcache); bei rekonstruierten Item-Objekten entfällt nur diese Zusatzprüfung.
    Günstige Felder werden aus `item.fields` beantwortet, unbekannte Feldnamen → `known:false`.
  - `applyUpdate`: Item mit der Schreib-Identity neu lesen, Labels case-insensitive vergleichen, nur fehlende per
    `POST …/labels` hinzufügen, vorhandene per `DELETE …/labels/{encodeURIComponent(name)}` entfernen (404 = schon
    weg → ok). Label in `add` **und** `remove` → wird hinzugefügt. Ergebnis `{changed, applied:{labelsAdded, labelsRemoved}}`.
  - `postComment`: Body + `\n\n<!-- <marker> -->` (Marker muss `[A-Za-z0-9_.:-]+` sein, passt zu `commentMarker`),
    `POST …/issues/{n}/comments` (Konversationskommentar, kein Review) → `CommentRef {id, url}`. Netzfehler/5xx →
    `outcomeUnknown: true`, kein Auto-Retry.
  - `findCommentByMarker`: alle Kommentarseiten, Marker muss auf eigener Zeile stehen (zitierte `> <!-- … -->` zählen nicht).
  - 401 auf API-Aufrufe → `credentials.invalidate(identity)` + genau ein Wiederholungsversuch.
  - Lesen mit Source-Identity (`config.identity`), Schreiben/Kommentar-Suche mit übergebener Identity.

## Bewusste Entscheidungen / Abweichungen
- HTTP-Client liegt in `src/sources/github/http.ts`; `src/identities` importiert ihn über `src/sources/index.ts`
  (keine Zyklen: sources hängt nur von core ab).
- API-Version `2026-03-10` (aktuelle Version laut GitHub-REST-Doku, Seite „Issue dependencies“). Vor Release prüfen (§24.1).
- `applyUpdate` nutzt `idempotent: true` für Label-POST/DELETE (GitHub-seitig idempotent), damit transiente Fehler
  automatisch wiederholt werden; `postComment` ist nicht idempotent → kein Auto-Retry, Abgleich über Marker (WI-07).
- `CredentialProvider` meldet transiente Fehler beim Token-Tausch als `transient`/`rate_limited` statt `auth`
  (Interface-Doku nennt nur `auth`), damit Retries greifen.
