# Handoff WI-02 – Konfiguration

Branch `wi-02-config`. Gate: `npm run check` grün (13 Testdateien, 156 Tests, davon 46 neu in WI-02; Review-Findings eingearbeitet).
Keine neuen Dependencies, **keine Änderungen an `src/core/`**.

## Umgesetzt

- **Schemas** (`src/config/schemas.ts`, zod 4, alle Objekte `strict` → unbekannte Keys/Tippfehler werden gemeldet):
  `config.yaml` (§5.1, §18), `sources.yaml` (§5.2, `type: github`), `identities.yaml` (§5.3, `type: github_app`),
  `workflows/*.yaml` (§5.4/5.5, inkl. aller 7 Hooks und 3 Action-Typen), `views/*.yaml` (§17).
  Filter-AST wird handgeschrieben validiert (`filter-schema.ts`), damit Fehler exakt auf den Knoten zeigen
  (`filter.all[1].operator`); prüft auch Operator/Wert-Kombinationen (`in` braucht Liste usw.).
- **Loader** `loadConfig(configDir, {dataDir, version?, clock?})` → `{ok:true, config, warnings} | {ok:false, errors, warnings}`.
  Wirft nie bei Konfigurationsfehlern; sammelt **alle** Fehler aller Dateien mit Datei (relativ zum Config-Dir),
  Pfad (`execute.timeout.max_duration`, `on_start[1].message`) und Zeilennummer. YAML-Syntaxfehler und doppelte Keys
  werden gemeldet; Dateien > 1 MiB abgelehnt; `maxAliasCount: 100`.
- **Normalisiertes Modell** (`model.ts`): camelCase, Dauern in ms, Größen in Bytes, `never` → `null`, nicht gesetzt →
  `null`, Defaults angewendet, `deepFreeze`. `LoadedConfig` hat `hash` (SHA-256 über kanonisches JSON), `version`,
  `loadedAt`, `workflowHashes` (pro Workflow, für Reload-Diff).
- **Semantische Validierung** (`validate.ts`): Referenzen Source→Identity, Workflow→Source/Identity,
  Secret→Identity, Action→Identity, View→Sources (existieren, eindeutig, gleicher Adaptertyp); eindeutige Workflow-,
  View-, Channel- und Action-IDs; Platzhalter je Kontext über `validateTemplate` aus core; Widersprüche (siehe unten);
  Cron via croner + Zeitzone via `Intl`; Parameter-Defaults passend zum Typ, Enum-Werte eindeutig;
  `ADISPATCH_`-Präfix in `env`/`secrets` reserviert; Name in `env` und `secrets` zugleich = Fehler.
  Warnungen (blockieren nicht): Workflow-ID ≠ Dateiname, `idle_timeout > max_duration`, Literal-Secret in `env`
  (Key sieht nach Secret aus, `isSecretKey` aus core), fehlende `config.yaml`.
- **ConfigManager** (`manager.ts`): `create()` (wirft `ConfigLoadError` mit allen Issues), `current`, `reload()`
  (serialisiert; nur bei Vollerfolg atomarer Austausch, sonst bleibt die aktive Config – auch dasselbe Objekt –
  unverändert), `onChange(listener)` (Events `reload` und `overrides`), Overrides `setWorkflowOverrides`,
  `clearWorkflowOverrides`, `setGlobalMaxConcurrent`, effektive Werte via `getWorkflow`/`listWorkflows`/`maxConcurrent`,
  `snapshotWorkflow`, `validateParameters`.
- **Snapshots** (`snapshot.ts`): `snapshotWorkflow(config, id)` → JSON-Kopie mit `schemaVersion`, `configHash`,
  `configVersion`, `workflowHash`, `workflow`, `source`, `workspace`, `identityRefs`. Enthält keine Identity-Details,
  keine Notification-Kanäle, keine Env-Werte von Secrets.
- **Parameter** (`parameters.ts`): `validateParameters(defs, input)` – Typprüfung, Defaults, Pflicht, unbekannte
  Parameter → Fehler; `"7"`→7 und `"true"/"false"` für Formulareingaben.
- **`toPublicConfig(config)`**: Kopie mit redigierten Literal-Webhook-URLs (für API/Logs in WI-10).
- **CLI** `config validate --config-dir <dir> [--data-dir <dir>]` (`src/cli/config-validate.ts`, verdrahtet in
  `main.ts`): Exit 0 = gültig (Warnungen auf stderr), 1 = ungültig mit Liste `datei:zeile: pfad: meldung`.
  In `program.ts` wurde `defaultIo` als `processIo` exportiert (sonst unverändert).
- **Beispielkonfiguration** `examples/config/` = Spec-Beispiele §5.1–§5.5, §17 (3 Workflows, 1 View).
  Ein Test extrahiert zusätzlich die YAML-Blöcke direkt aus `docs/spec-v0.1.md` und validiert sie.

## Platzhalter-Scopes (für WI-07/08 beim Rendern verbindlich)

| Feld | Modus | Verfügbar zusätzlich zu `always` |
|---|---|---|
| `execute.working_directory` | `path` | `run`, `source` (nur Source-Trigger), deklarierte `parameters`, die `required` sind oder einen Default haben; Template muss mit `/` oder `{workspace.base_dir}` beginnen |
| `execute.args`, `execute.env` | `text` | `run`, `workspace`, `source`*, `parameters` |
| Hook-Actions (`message`, `args`, `env`) | `text` | `run`, `workspace`, `source`*, `parameters`, `result` (**nicht** in `on_start`) |
| `conditions.workflow[].args` | `text` | – |
| `conditions.item[].args` | `text` | `source` |

\* `source` nur bei `trigger.type: source`. `command`-Felder werden nicht als Template behandelt.

**Kommandopfade** (`execute.command`, `conditions.*.command`, `shell_filter.command`, `shell`-Action-`command`):
absolute Pfade werden normalisiert; relative Pfade mit `/` (`scripts/coder.sh`, `./x.sh`, `../y.sh`) werden
relativ zum Config-Dir aufgelöst; reine Namen ohne `/` (`bash`) bleiben unverändert für PATH-Lookup durch den Executor.
Das Modell enthält also nur absolute Pfade oder reine Namen.

## Bewusste Entscheidungen / Abweichungen

- **Widersprüche (Fehler):** `filter`, `shell_filter`, `item_priority`, `conditions.item`, `source.update`,
  `source.comment` nur bei Source-Trigger; `shell_filter` in Views; Pflichtparameter ohne Default in automatisch
  getriggerten Workflows (Source/Schedule könnten ihn nie liefern); `source.update` ohne Labels oder mit demselben
  Label in add und remove.
- **Override-Reset beim Reload (pro Feld):** Ein Override (`enabled`, `priority`, `maxConcurrent`) wird nur
  zurückgesetzt, wenn sich genau dieser konfigurierte Wert geändert hat; andere Änderungen am Workflow lassen
  Overrides bestehen. Entfernte Workflows verlieren alle Overrides. Globales `max_concurrent`-Override wird
  zurückgesetzt, wenn sich `scheduler.max_concurrent` ändert. `ReloadResult.resetOverrides` listet die Workflow-IDs
  mit mindestens einem zurückgesetzten Override, sortiert, danach ggf. `"*"` (global).
- **Weitere Fehler:** `cache` bei `conditions.item` (wirkt dort nicht); `execute.timeout.max_duration`/`idle_timeout`
  müssen > 0 sein. Skalare Enum-Defaults werden wie die `values` zu Strings (`values: [1, 2]`, `default: 1` ist gültig).
- **Snapshot ohne Overrides** – Overrides betreffen nur Scheduling, nicht laufende Runs.
- **`identity` bei `source.comment`** bleibt im Modell `null`, wenn nicht gesetzt; Fallback-Reihenfolge
  Action → Workflow → Source löst der Aufrufer (WI-07) auf.
- **Kein Lesen von Env-Variablen im Loader** → Secrets können nicht im Modell/in Meldungen landen. Ausnahme:
  Literal-`url` eines Webhook-Kanals steht im Modell (wird zum Zustellen gebraucht); nach außen nur über
  `toPublicConfig`; Fehlermeldungen geben die URL nie wieder. Literal-Werte in `execute.env` sind keine Secrets
  (dafür gibt es `secrets:`), werden aber bei verdächtigen Namen als Warnung gemeldet.
- **Feldnamen in Filtern/Views** werden offline nicht gegen Adapter-Felddefinitionen geprüft (Adapter sind beim
  Validieren nicht verfügbar) – optionaler Capability-Check später (§19 „API-Capabilities separat“).
- `config validate` ohne `--data-dir` nimmt `./data` nur für den Default von `workspace.base_dir` an; ohne
  `--config-dir` Exit 1.
- Top-Level-Dateien nur als `.yaml`; in `workflows/` und `views/` werden `*.yaml` und `*.yml` gelesen.
- `sources.yaml`/`identities.yaml` dürfen fehlen (z. B. reine Cron-Setups); fehlende `config.yaml` → Warnung, Defaults.
