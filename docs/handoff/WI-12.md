### systemd (`src/service/`)
- `renderSystemdUnit(opts)` (rein): `ExecStart=<node> <entry> start --config-dir … --data-dir … --drain-timeout … --cancel-timeout …`
  (systemd-Quoting, `%`/`$` escaped, Zeilenumbrüche abgelehnt), `User`/`Group`, `WorkingDirectory=<data-dir>`,
  `EnvironmentFile=-/etc/default/<name>` (optional), `Restart=on-failure`, `RestartSec=5s`, `KillMode=mixed`,
  `KillSignal=SIGTERM`, `TimeoutStopSec = ceil(drain + cancel + max cancel_grace + 60 s)`, `UMask=0027`,
  `NoNewPrivileges`, `PrivateTmp`, `LimitNOFILE`. `validateUnitOptions` lehnt `npx`/`_npx`-Pfade, relative Pfade, `.ts`-Entry,
  `root` als Benutzer und ungültige Namen ab.
- `planInstall(input)` → Schritte als Daten: ggf. `useradd --system --user-group --no-create-home --shell /usr/sbin/nologin`
  (nur mit `--create-user`, sonst Fehler mit Hinweis bzw. Note im Dry-Run), `install -d -m 0750 -o user` + `chown -R` data-dir,
  config-dir `chown -R root:<group>` + `chmod -R u=rwX,g=rX,o=`, Env-Datei-Vorlage (nur wenn nicht vorhanden) 0640
  root:<group>, Unit 0644, `systemctl daemon-reload`, `systemctl enable [--now]`.
- `planUninstall` → `systemctl disable --now` (optional), Unit-Datei löschen, `daemon-reload`; config/data/user bleiben.
- `executePlan(plan, runner, log)` über injizierbaren `SystemRunner` (`execFile` ohne Shell); `formatPlan` für `--dry-run`.

## Entscheidungen
- **`test:pack` als eigenes Script statt im Gate:** braucht `npm` mit Registry-Zugang oder gefülltem Cache (sonst
  netzabhängiger Fehlschlag), baut per `prepack` `dist/` neu (`rm -rf dist`) – im Gate würde das parallele Läufe/Builds im
  selben Checkout stören. Es ist schnell (≈ 10 s) und gehört vor jeden Merge/Release ausgeführt. Im normalen `vitest run`
  wird die Datei übersprungen (`describe.skipIf(!ORCH_PACK_TEST)`).
- **Drain-/Cancel-Timeouts als CLI-Flags** (`start`, `service install`), nicht in `config.yaml`: Die Unit braucht sie
  ohnehin für `TimeoutStopSec`; so stimmen Unit und Prozess immer überein, und `src/config` bleibt unverändert.
  `service install` liest `cancel_grace` aus der Config – nach Änderung neu installieren (dokumentiert).
- **Init-Templates als Code** statt Dateien im Paket; `examples/config` (WI-02, Spec-Beispiele) bleibt als Referenz im Paket.
- Init-Konfiguration startet ohne GitHub-Credentials (nur `hello` aktiv); GitHub-/Cron-Beispiele `enabled: false`.
- Env-Datei-Default `/etc/default/<name>` (außerhalb config-dir: Secrets getrennt von der versionierbaren Konfiguration,
  die per git/Backup weitergegeben wird); `--env-file none` deaktiviert.
- Unit-Härtung bewusst moderat (`NoNewPrivileges`, `PrivateTmp`, `UMask=0027`); `ProtectSystem` etc. per Drop-in.
- `service status` = `systemctl status` (read-only); `uninstall` löscht nie Daten/Benutzer.
- `workflow dry-run` versucht standardmäßig die laufende Instanz (WI: „Default aus config, Fallback lokal“).

  ablegt oder `uiDir` selbst in `start.ts`/`app.ts` verdrahtet, beim Merge auf eine Stelle reduzieren (`defaultUiDir`).
- Linux/systemd nicht ausgeführt (macOS-Host, absichtlich keine echten systemd-Änderungen): `docs/manual-tests/systemd.md`
